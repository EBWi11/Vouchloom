# Project One Fixture-backed Carrier

Use the retained route and one disclosed fixture. Do not infer a different target,
format, fault condition, or carrier.

1. Identify the project reader or writer that defines the complete outer carrier.
2. Verify one unchanged fixture reaches the bound parser, using an existing
   executable when available or one exact source readback otherwise.
3. Bind the inner relation to one project-writer parameter or an exact half-open
   byte or bit span. If neither is established, return a coordinate gap.
4. Change only the innermost source-backed relation from the active construction
   gap. Use the project writer when it preserves more invariants than byte edits.
5. Repair only fields that directly depend on that change: lengths, offsets,
   checksums, indexes, chunk tables, or framing metadata.
6. Materialize `/work/poc.bin`, read back the changed relation and dependent
   fields, record the construction evidence, and stop.

## CFI readback

For an ELF carrier with a source-proven CFI route, run:

```text
python /codex-home/skills/fixture-backed-carrier-projection/scripts/read_elf_cfi.py <artifact>
```

Use it to read section, CIE/FDE, and augmentation boundaries. The script is
read-only and cannot choose or generate a changed value.

Use one fixture, one representation, and one projection attempt. Never launch a
broad build, install or repair dependencies, generate multiple format variants,
or treat writer success as vulnerability evidence. If the baseline carrier or
inner relation is not source-backed, return a precise construction gap instead
of manufacturing bytes.
